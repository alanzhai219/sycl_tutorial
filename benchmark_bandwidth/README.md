# SYCL GPU 内存带宽微基准

只测 GPU 连续读、连续写的持续有效带宽，不测 CPU/GPU 之间的 memcpy。

## 构建

在本目录运行，要求 Intel oneAPI DPC++/SYCL 编译器和可用 GPU 驱动：

```bash
source /opt/intel/oneapi/setvars.sh --force
icpx -O3 -std=c++17 -fsycl main.cpp -o bandwidth
```

## 运行

```bash
./bandwidth
./bandwidth 0 512 30
```

不带参数时列出 GPU。参数依次为设备编号、数组大小（MiB，默认 512）、测量次数（默认 30）。始终先测读，再测写。

同一 GPU 可能通过 Level Zero 和 OpenCL 重复列出，选择一个即可。多个测试应串行运行。

读写共用一个 FP32 device USM 数组，另有大小为它 1/1024 的校验和数组。程序检查单次分配限制，并保守限制主数组不超过报告设备内存的 20%。

可扫描大小以观察大工作集的平台区：

```bash
for mib in 128 256 512 1024; do
    ./bandwidth 0 "$mib" 30 || break
done
```

## 测量方式

- 每个 work-item 用 `float4` 处理 4 个元素，工作组大小为 256。
- Read：读取整个数组，每 1024 个元素归约为一个校验和，避免读取被优化掉。报告的带宽只计输入字节，不计约 0.1% 的校验和写流量。
- Write：不读输入数组，按索引生成伪随机值后写入。初始化 seed 为 17，写测试 seed 为 101，确保校验能区分写入结果与初始内容。
- 使用 [1, 2) 内具有 23 位伪随机尾数的 FP32 数据，降低常量和重复模式带来的可压缩性，但不保证完全不压缩。
- 每项预热 5 次，使用 GPU event 的 `command_end - command_start` 测量，输出中位时间及对应的 GB/s。
- 带宽 = 主数组字节数 / 中位 kernel 时间秒 / 1e9。分配、初始化和结果回读不计时。
- 校验全部读校验和及写输出；写输出精确比较，读校验和与 double 参考值比较，允许 1e-5 的相对误差。

## 结果的边界

- 这是算法有效带宽，不是硬件计数器实测 DRAM bytes。缓存、写入策略和物理事务粒度会让两者不同。
- 数组应明显大于相关缓存；小规模结果可能是缓存带宽。程序打印的全局缓存属性不保证涵盖所有相关缓存。预热不会清空缓存，kernel 完成也不保证所有写入已落到 DRAM。
- Read 有归约开销，Write 有数据生成开销，不保证达到硬件极限。
- iGPU 的 DDR 与 CPU、显示等共享。关闭其他 GPU 任务及 CPU 内存压力，并保持电源和散热条件一致。
- 严格测量 DRAM 流量仍需平台支持的内存控制器计数器；GTI 流量不自动等于 DRAM 流量。
